# 崩塌实验室 · 承重连锁版 v8.7

[手机直接试玩](https://fcg-atk.github.io/skyfall-lab/) · [源码仓库](https://github.com/fcg-ATK/skyfall-lab)

面向手机浏览器的 3D 建筑破坏游戏，支持横竖屏和电脑鼠标操作。全部运行资源随仓库提供，无外部 CDN、账号或后端依赖。

每轮四发弹药，绕楼选择撞击点，观察局部破坏，再寻找下一处关键支撑。普通命中可以留下稳定残楼；关键承重失效则可引发整楼坍塌，包括一发全毁。四发是上限，不是强制补刀次数。

本版提供可关闭的承重提示，说明所选楼体的下方支撑、上方承托与承重吃紧位置。细长残柱失去横向约束时会重新计算承载能力。三种弹体实际穿过并接触到的背面结构均会破坏，同一区块只计分一次，打空不扣弹药。

按块固定计分，全毁额外奖励剩余弹药×300；评级 S=全毁，A≥80%，B≥60%，其余C。每发结束直接回到瞄准状态，只有全毁或弹药用尽才弹出结算。

发布前已通过266项自动检查及桌面浏览器横竖屏布局和试玩检查；真实Android/iPhone与微信浏览器的帧率和手感仍需要实机验证。结构为游戏近似，不用于工程分析。

## 操作

- 单指拖动：环绕建筑并调整俯仰；双指捏合：缩放；双指整体上下移动：升降观察高度。
- 轻点建筑：选择撞击点。金色箭头显示发射方向，绕楼可以改变方向。点空立即提示未选中，瞄准环闪红后变灰，按钮禁用并提示重新瞄准；此时仍可打的楼体显示暖色提示。
- 「瞄准」：设置撞击高度与倾角；正角度从高处俯射，可用的上仰角随高度变化。目标高亮在需要重新瞄准时自动出现。唯一的辅助瞄准开关默认关闭；开启后支持附近有效楼体的点选辅助，以及单发结束后的失效目标自动恢复。发射预检为空时不扣弹药。
- 「承重提示」：默认开启，在「瞄准」面板独立开关。选中有效结构后显示当前支撑关系，青色表示仍在承重，橙色表示承重吃紧；发射、暂停、帮助与结算时隐藏。
- 火箭：瞄准中下部承重列，含命中层最多沿列切入三层，遇空隙停止；陨石：冲击底部较大范围；铁球：集中撞击承重结构，可从不同方向补刀。只有实际撞到建筑才造成损坏。
- 命中时短暂慢动作；每轮 4 发，单发稳定后自动恢复发射，HUD 显示进度；全毁或弹药用尽后结算，结算面板可直接重建再试。
- 默认「平衡」最高 30 帧；「省电」降低像素与细粒并关闭实时阴影；「精细」最高 60 帧。画质只按手动选择切换。
- 电脑也支持鼠标拖动与滚轮。音效在首次主动操作后启用。

横竖屏均可使用。需要支持 WebGL 2 的现代浏览器；手机内置浏览器无法启动时，可以改用系统浏览器。若设备发热或掉帧，请切换「省电」。

手机启动会显示实际下载量。支持原生 gzip 解压的浏览器只需下载约 8.3 MB 的核心模型数据（原始约 32.1 MB），解压结果与原模型逐字节一致；旧浏览器自动使用原文件。街区贴图后台加载，不再阻挡进入场景。网络长时间无进展、模型解码超时或图形上下文丢失时会显示重试提示。安卓微信内仍无法进入时，可点右上角“…”选择“在浏览器打开”；桌面测试不能代替具体手机和微信版本的实测。

## 本地运行

安装 Node.js 22 或更新版本。在仓库根目录运行：

```sh
node tools/serve.cjs
```

在浏览器打开 [本地预览](http://127.0.0.1:5192/) 或 [带调试面板的预览](http://127.0.0.1:5192/?debug=1)。停止服务时按 `Ctrl+C`。该服务仅监听本机。

不需要 `npm install`。本地服务启动会先运行 `node tools/prepare-assets.cjs`，生成无损压缩的资源副本。`dist/` 中的游戏 JavaScript、HTML、CSS 可以直接编辑，刷新页面即可看到结果。由于浏览器资源加载限制，请通过 HTTP 服务打开页面，不要直接双击 `index.html`。

运行自动检查：

```sh
node --test tests/*.test.cjs
```

测试覆盖规则、结构支撑、碎块数据与运动、三种发射物、打空零伤害、重置、音效触发、触控处理及固定资源预算。图形相关测试使用真实模型与 Three.js，但 WebGL 渲染器和部分浏览器对象使用替身；这些测试不验证真实 GPU 图像、浏览器触摸事件链或手机帧率。

## GitHub Pages 部署

仓库附带 `.github/workflows/deploy-pages.yml`：

1. 在仓库的 **Settings → Pages → Build and deployment** 中，把 **Source** 设为 **GitHub Actions**。
2. 向 `main` 分支推送更新，或在 **Actions → Deploy GitHub Pages → Run workflow** 手动运行。
3. 工作流先运行测试，再将完整 `dist/` 发布为网站。部署完成后，在 Pages 设置或工作流的 deployment 链接中打开网站。

详细配置见 [GitHub Pages 官方文档](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。普通静态托管服务也可以直接使用完整 `dist/` 文件夹；不要只上传入口 HTML 或压缩包。

## 模型与物理边界

完整楼体分为 48 个结构区域，破碎时使用 3,337 块结构碎片与 2,296 块玻璃，共 5,633 块、194,181 个三角形。碎块继承建筑的平移与旋转，经过简化接触、滑动与滚动后保留为废墟，直至重建；渲染使用两批合并网格和共享变换纹理。

本项目采用游戏近似：支撑关系、承重连接、倾斜承托面和废墟堆积均经过简化，碎块之间没有逐对精确碰撞。它不用于建筑工程分析。帧率档位是上限，不代表所有设备都能达到；尚未完成真实 Android 与 iPhone 设备的帧率测量。

仓库提供运行所需的完整模型与纹理，可直接运行、修改游戏逻辑和替换兼容资产。原始 Blender/PC 制作工程及依赖这些工程的导出脚本没有随本仓库分发，因此本仓库不提供从原始 DCC 工程重建全部美术资源的流水线。资产格式与来源见 [建筑说明](dist/assets/ARCHITECTURAL-ASSETS.md)、[碎块说明](dist/assets/PC-FRAGMENTS.md) 和 [环境来源](dist/assets/env-SOURCES.md)。
